## Explicitly *not* going to be built

Recorded so they are not repeatedly reconsidered:

- **Ruler-and-compass constructions** (NCERT Ch. 8) — teaches phone skills, not
  geometry.
- **Free-text explanation** — cannot be graded offline, deterministically, or
  equally across languages. Shipping it ungraded would be theatre.
- **Coins / gems / energy / leaderboards / purchasable streak freezes** —
  undermine intrinsic motivation, and several are ethically inappropriate for
  children.
- **Sound design** — needs authored assets, a mute control and silent-switch
  handling. System beeps were judged worse than silence.
- **Mascot / illustration set** — needs a designer, not a generator.

## Implementation log

### Batch 1 — Group A (progression wiring) and Group B (visual layer)

**Tests 396 → 429.** Typecheck clean. Verified in Chromium.

#### Group A · the economy is now live

docs/16 was fully designed and simulated but touched nothing. Now wired:

- `progression/award.ts` — a single `awardXp` orchestrator. `computeXp` takes
  seven inputs and the anti-grind suppressors are four more functions;
  assembling them at the call site would have meant every screen understanding
  the whole economy, and any screen getting it subtly wrong would silently
  mis-pay.
- **The high-water ledger is persisted** (`paidHighWater`). This is the *one*
  piece of progression state that must survive a restart — everything else
  (level, mastery index, achievements) is derived from the attempt log. Without
  it, a learner could let a skill decay and re-earn the same Δ forever.
- Bonus events surface in the feedback panel, named as achievements
  ("Breakthrough", "First try") rather than as mechanics.

**Bug caught during browser testing:** XP was being computed inside a
`setAttempts` updater. React may invoke an updater twice (StrictMode,
concurrent rendering), which would have **double-counted XP and corrupted the
ledger**. Moved outside, with refs mirroring the log and running total so the
award path never reads stale state. Verified live: `+169.8 XP` with `First try`
and `Breakthrough`.

#### Group B · the visual layer

The audit found **0 visual representations** in the product — the app went
straight to the Abstract stage of CPA with no Concrete or Pictorial step.

Four SVG primitives, all on the existing `react-native-svg` dependency:
`NumberLine`, `PartModel` (bar / circle / set), `ArrayGrid`, `BaseTen`.

`learning/visualPolicy.ts` implements the **fade rule**, which is what makes
these pedagogy rather than decoration:

```
mastery < 0.55  →  interactive     0.55–0.80  →  illustrative     > 0.80  →  none
```

The withdrawal is required, not politeness: expertise reversal means visual
support that persists past competence *reduces* performance.

Skills deliberately given **no** visual are recorded with reasons in
`NO_VISUAL_BY_DESIGN`, so the omission reads as a decision:
times tables (automaticity is the goal — a visual slows retrieval), word
problems (building the model from text *is* the skill), algebra (single-step at
this level).

`QuestionVisual` bails out rather than guessing whenever the question text does
not yield sensible parameters. A visual that misrepresents the problem is worse
than none — it would actively teach the wrong thing.

**Deliberately not built:** interactive visuals where the visual *is* the answer
surface ("tap where 0.45 goes"). That is a larger change to the answer pipeline,
and a visual a child can tap but which is not graded would be worse than none.
Currently illustrative mode only.

**Bug caught in the browser:** `PartModel` reserved label space unconditionally,
so a fraction bar lost a quarter of its height and collapsed into an unreadable
strip. Now reserved only when a label is drawn.
